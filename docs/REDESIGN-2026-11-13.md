# UI redesign: 2026-11-13

Why: the mobile app was a visual copy of another company's product (name, yellow/green palette,
Poppins, component names, promo carousels) and the web landing reused another company's marketing
copy. Neither can go to production. Both clients now share one original design system
([DESIGN-SYSTEM.md](DESIGN-SYSTEM.md)). **The backend was not touched.**

## What changed

### Both platforms
* One token set: brand teal `#0F766E`, slate neutrals, emergency red reserved for SOS and
  destructive actions, Inter, 4-pt spacing, 12/16/24 radii, two elevations.
* New logo mark (pin with cross), app icons, adaptive icons, splash and favicon.
* **Safety strip** on home, request and tracking: one-tap **Call 112** and **Share my location**
  (system share sheet with a maps link; no backend, no account).
* Status is icon + word + colour everywhere; 44/48px touch targets; reduced-motion respected.
* Brand-hygiene tests (`web/tests/services/brand-hygiene.test.ts`, `mobile/tests/brand-hygiene.test.ts`)
  fail the build if another company's name, the old palette or typeface, stock partner photos or
  invented money (coupons, GSTIN, wallet, tips) come back.

### Web
* New landing page: honest copy, live service catalogue from `GET /services` (with loading, error
  and retry states), tracker illustration with no invented people or times, partner section. Old
  landing files, `landing.css`, `auth.css`, the wrench cursor and stock photos are deleted.
* Login rebuilt: **no pre-filled phone numbers outside the dev server**, and **Resend now actually
  re-sends** (it only reset the timer before).
* Owner shell: top nav + phone bottom tab bar; Home shows the primary action, safety strip and any
  in-flight request first; history rows are real links.
* Request page: **no default pin** (it used to silently dispatch to central Bengaluru), typing a
  landmark can no longer invent coordinates, **no fallback service catalogue** (a failed load
  shows retry instead of offering made-up services), no emoji.
* Tracking page: native `confirm()`/`alert()` replaced with the in-app dialog, real star rating,
  plain-language status copy.
* Partner console: the stock aerial photo with a decorative route is replaced by an honest
  dispatch-status card; dead "Messages" button, dead search box, stock portraits, the hard-coded
  "Indiranagar Hub" and the fabricated "Live (1m ago)" GPS label are gone; type floor 12px;
  responsive sidebar becomes a tab strip on phones.
* **Partner registration, verification and preferences rewritten against the backend.** The old
  versions showed fiction: a document-upload step whose files went nowhere (followed by "your
  documents are in review"), an "Autofill sample docs" and "Fill sample" button, a "1800-SAHAYAK"
  partner desk number, invented proof stats ("500+", "₹8,400", "15 Mins"), and operational
  defaults shown as facts ("East Bengaluru", "Up to 3.5 Tonnes", 20 km radius). Now: phone code →
  name and main work → services from the live catalogue → register (`POST /partners`, link-auth,
  services). Verification shows the real `verification_status`. Preferences reads and writes the
  partner's linked services (`GET /partners/me/services`, `POST /partners/{id}/services`).
  Equipment is not collected because no endpoint stores it.
* **Terms of Service and Privacy pages** (`/terms`, `/privacy`), linked from login, the landing
  footer and (when `EXPO_PUBLIC_WEB_URL` is set) the mobile login and Account screens. They state
  only what the product actually does (ADR-017 contact release, location use, no file uploads).
* Login honours a same-site `?redirect=` to an owner page, so "Request help" → sign in → back to the
  request, with no open redirect.
* Admin console: removed the hard-coded "Operations Lead" identity and "PostGIS Engine · Supabase
  Auth" label; it no longer renders inside the owner shell.
* Partner and admin routes are lazy-loaded (main bundle 730 kB → 557 kB).

### Mobile
* Owner tabs rewritten on real data: Home, Services ("What happened?" symptom helper + live
  catalogue), Activity (history, details sheet, cancel with reason, rate), Account (profile,
  vehicles, privacy, sign out), notifications from the bell.
* Request flow rewritten (map + sheet): required pickup, service, vehicle, optional notes; searching,
  matched (partner, call, start code, progress), done (rating). **Resumable** from Home after the
  app is closed. Cancel and rating go through the real API.
* Partner home rebuilt (shift toggle confirmed by the backend, GPS report, 15s offer poll, active
  job, standing, earnings, services); offer / active-job / done screens re-themed, price shown only
  when the backend has one, real map instead of the vector canvas.
* Login rebuilt: **new owners can now register in the app** (before, an unregistered owner was let
  in with a fabricated local profile and every call failed); a network error no longer signs
  anyone in with a fake identity; no pre-filled number in production builds.
* Removed fabricated content: wallet balance, saved payment methods, coupons, GSTIN and invoice
  links, tips, ₹299 default price, "for you" carousels, fake ambient partner dots, 5-star default
  rating.
* Removed the public OSRM demo server (no SLA, forbids production traffic). Routing now uses
  `EXPO_PUBLIC_ROUTING_URL` if you operate one, else a straight connector.
* Google Maps API key moved out of `app.json` into `app.config.js` (env). Unused permissions
  (camera, storage, always-on location) removed.

   to the package name / bundle id.
2. **Legal review of `/terms` and `/privacy`.** They are written from what the product does, not
   by counsel. Neither has a contact or grievance address because the product has no support
   channel yet: add one (email or phone) and name it in both pages and in the apps.
3. Run on a device: request → match → start code → complete → rate, both roles.
4. Set `EXPO_PUBLIC_WEB_URL` (mobile) so the apps can open the legal pages, and
   `EXPO_PUBLIC_ROUTING_URL` if you run a routing service (otherwise straight connectors).
5. Partner mobile sign-up is web-only; the app says so. Equipment and documents are verified by
   the Sahayak team outside the product today.
